# 하루하루 일본어 — Supabase 자동 동기화 버전

목적: 원본의 30개 수업, 듣기, 로마자 입력, 퀴즈, 오답 노트, 자유 수업 선택, 달력, JSON 백업 기능을 유지하면서 PC와 휴대폰의 기록을 연결합니다.

현황: 코드는 완성되어 있으며 기본값은 로그인 없는 로컬 모드입니다. 본인의 Supabase 프로젝트를 만들고 아래 공개 연결값 두 개를 입력하면 실제 계정 동기화가 동작합니다. 계정을 만들거나 실제 서비스에 배포하는 작업은 이 ZIP에 포함된 테스트와 별개입니다.

제안: 기존 GitHub + Vercel 조합을 유지하고 Supabase만 추가합니다. 설치나 빌드가 필요 없는 HTML 사이트입니다.

## 처음이라면 여기부터 읽습니다

이 안내에서 **배포**는 만든 파일을 인터넷에 올려 주소로 접속할 수 있게 하는 작업입니다. **GitHub 저장소**는 사이트 파일을 보관하는 폴더이고, **Vercel**은 그 파일을 웹사이트로 보여주는 서비스이며, **Supabase**는 로그인과 학습 기록을 보관하는 서비스입니다.

| 준비할 것 | 용도 |
|---|---|
| 이 ZIP을 푼 폴더 | 업로드할 사이트 파일 |
| GitHub 계정 | 파일 보관 |
| 기존 Vercel 계정 | 사이트 주소와 운영 |
| Supabase 계정 | 이메일 로그인과 기기 간 진도 공유 |
| 로그인 메일을 받을 이메일 | PC와 휴대폰에서 같은 계정으로 로그인 |

**이미 Vercel 사이트가 있다면 새로 만들지 않고 기존 GitHub 저장소의 파일을 교체하는 방법이 가장 간단합니다.** 운영 주소가 유지되어 기존 브라우저 기록을 가져오기에도 좋습니다.

### 화면을 따라 하는 쉬운 진행 순서

1. ZIP 파일을 다운로드합니다. Mac에서는 ZIP을 더블 클릭하면 폴더가 풀립니다. Windows에서는 ZIP을 마우스 오른쪽 버튼으로 눌러 **모두 압축 풀기**를 선택합니다.
2. 풀린 폴더를 열어 `index.html`과 `config.js`가 보이는 위치를 찾습니다. 이 파일들은 실행하지 않고 업로드할 것입니다.
3. 현재 일본어 사이트에서 **데이터 관리 → 학습 기록 JSON 백업**을 눌러 기존 진도를 보관합니다.
4. 아래 2절을 따라 Supabase 프로젝트를 만들고, `schema.sql`을 열어 내용을 전부 복사한 뒤 SQL Editor에 붙여넣고 **Run**을 누릅니다. SQL은 학습 기록을 담을 보관함과 계정별 잠금장치를 만드는 설명서라고 생각하면 됩니다.
5. 아래 4절을 따라 GitHub의 기존 저장소에 폴더 안의 파일·하위 폴더를 전부 업로드합니다. 웹 업로드에서 숨김 파일을 선택하지 못해도 실행에는 지장이 없지만, `fonts`와 `vendor` 폴더는 반드시 포함합니다.
6. GitHub 저장소의 파일 목록에서 **config.js → 연필 아이콘(Edit this file)**을 누릅니다. 아래 3절의 예시처럼 빈 따옴표 안 두 곳에 본인의 Project URL과 Publishable key를 붙여넣습니다. 작은따옴표·쉼표·괄호는 그대로 둡니다.
7. GitHub 편집 화면의 **Commit changes… → Commit changes**를 누릅니다. 가능하면 기존 운영 브랜치인 `main`에 반영합니다. 이 버튼은 수정한 파일을 저장하는 버튼입니다.
8. 기존 Vercel 프로젝트라면 **Vercel → 해당 프로젝트 → Deployments**에서 맨 위의 배포가 **Ready**가 되는지 확인한 뒤 **Visit**을 누릅니다. GitHub와 아직 연결하지 않았다면 아래 5절의 새 프로젝트 절차를 진행합니다.
9. 브라우저 주소창의 정식 사이트 주소를 복사해 아래 6절의 Supabase **Site URL**과 **Redirect URLs**에 등록하고 **Save**를 누릅니다. Preview 주소 대신 평소 사용할 고정 주소를 사용합니다.
10. 사이트에서 **메뉴 → 데이터 관리 → 이메일로 가입 · 로그인**으로 메일을 받고 링크를 누릅니다. 로그인 후 **이 기기의 기존 기록 가져오기**를 누르고, 휴대폰에서도 같은 주소·같은 이메일로 로그인합니다.

완료 기준은 PC에서 **동기화 완료**가 표시되고, 휴대폰에서 같은 완료 수업이 보이는 것입니다. 로그인 없이 화면만 열리는 것은 Supabase 연결 완료를 뜻하지 않습니다.

### 사용 방법

| 하고 싶은 일 | 누를 곳 |
|---|---|
| 완료한 수업을 다시 듣기 | 전체 수업 → `✓ 학습 완료` 수업 선택, 또는 복습 · 오답 노트 → 완료한 수업 |
| 예전에 공부한 날짜의 수업 다시 듣기 | 학습 캘린더 → 해당 날짜 → `DAY 번호 다시 듣기` |
| 컴퓨터 메뉴 | 화면 왼쪽에 고정 표시 |
| 모바일 메뉴 | 왼쪽 위 `☰` → 원하는 메뉴 선택; `✕`나 바깥 영역으로 닫기 |
| 글씨체 | 프리텐다드 폰트 파일을 사이트에 포함, 별도 설치 불필요 |

일본어 글자와 이모지는 프리텐다드가 지원하지 않는 경우 기기의 일본어·이모지 글꼴로 표시됩니다. 수업을 다시 열어도 기존 완료 기록은 유지되며, 다시 완료하기를 누르면 그날 달력에도 학습 기록이 추가됩니다.

## 1. 기존 기록을 먼저 백업합니다

1. **현재 사용하던 사이트 주소**를 기존 브라우저에서 엽니다.
2. 데이터 관리 → `학습 기록 JSON 백업`을 눌러 파일을 보관합니다.
3. 가능하면 기존 Vercel 프로젝트와 주소를 그대로 유지합니다. 브라우저 저장소는 주소별로 분리됩니다.
4. 기존 ZIP도 별도로 보관합니다. 이 업데이트의 원본 수업 내용은 변경하지 않았습니다.

기존 파일을 더블 클릭해서 사용했다면, 그 파일에서 먼저 백업합니다. `file://`로 보던 기록은 배포 주소로 자동 이동하지 않으므로 JSON 복원이 필요합니다.

## 2. Supabase 프로젝트를 준비합니다

1. https://supabase.com/dashboard 에 로그인하고 **New project**를 선택합니다.
2. 프로젝트 이름과 데이터베이스 비밀번호를 정하고 프로젝트가 준비될 때까지 기다립니다. 데이터베이스 비밀번호는 사이트 파일에 넣지 않습니다.
3. 왼쪽 **SQL Editor → New query**를 엽니다.
4. ZIP의 `schema.sql` 전체를 붙여넣고 **Run**을 누릅니다.
5. **Table Editor**에서 `study_progress`가 생겼는지 확인합니다. 이 표에는 계정마다 한 행씩 기록이 저장됩니다.
6. **Authentication → Sign In / Providers**에서 **Email** 로그인이 켜져 있고 새 가입이 허용되어 있는지 확인합니다. 대시보드 버전에 따라 항목명이 다를 수 있습니다.

SQL은 같은 파일을 다시 실행해도 기존 학습 기록을 지우지 않습니다. 테이블 접근은 로그인한 사용자의 `auth.uid()`와 `user_id`가 같은 경우로 제한하며, 비로그인 사용자는 기록을 읽거나 쓸 수 없습니다. 저장 함수는 `security invoker`로 실행되어 동일한 접근 제한을 받습니다.

근거: [Supabase 행 접근 제한](https://supabase.com/docs/guides/database/postgres/row-level-security), [데이터베이스 함수](https://supabase.com/docs/guides/database/functions).

## 3. 공개 연결값 두 개만 입력합니다

프로젝트의 **Connect** 또는 **Project Settings → API / API Keys**에서 Project URL과 Publishable key를 찾습니다.

`config.js`를 텍스트 편집기로 열고 다음 두 값을 채웁니다. 파일 편집이 낯설다면 앞의 쉬운 진행 순서 6~7번처럼 GitHub 웹 화면의 연필 버튼으로 수정해도 됩니다.

```js
window.STUDY_CONFIG = {
  supabaseUrl: 'https://본인프로젝트.supabase.co',
  supabasePublicKey: 'sb_publishable_본인공개키'
};
```

| 값 | 넣는 위치 | 공개 저장소에 올려도 되는지 |
|---|---|---|
| Project URL | `supabaseUrl` | 가능 |
| Publishable key (`sb_publishable_...`) | `supabasePublicKey` | 가능, 반드시 제공한 SQL의 접근 제한을 적용합니다 |
| 기존 legacy `anon` 키 | Publishable key 대신 사용 가능 | 가능, 역할이 `anon`이어야 합니다 |
| Secret key, `service_role` 키, DB 비밀번호 | **어디에도 입력하지 않습니다** | 불가 |

이 사이트는 비밀 키와 `service_role` 키의 사용을 차단합니다. 공개 키는 브라우저에 보이는 것이 정상이며, 계정 토큰과 데이터베이스 접근 제한이 개인 기록을 보호합니다. 만약 비밀 키를 이미 GitHub에 올렸다면 삭제만 하지 말고 Supabase에서 해당 키를 폐기·교체해야 합니다.

[Supabase 공식 API 키 설명](https://supabase.com/docs/guides/getting-started/api-keys).

Vercel의 Environment Variables에 값만 입력해도 이 HTML에 자동 반영되지는 않습니다. 이 버전에서는 **`config.js` 자체를 수정**합니다.

## 4. GitHub에 업로드합니다

1. ZIP을 풀고 `japanese-study` 폴더를 엽니다.
2. 기존 GitHub 저장소를 엽니다. 신규라면 https://github.com/new 에서 저장소를 만듭니다.
3. **Add file → Upload files**를 누릅니다.
4. 폴더 **안의 내용 전체**를 올립니다. `index.html`, `config.js`, `sync.js`, `sync-core.js`, `sw.js`, `vercel.json`, `vendor/`, `fonts/`, `schema.sql`, `README.md`, `TEST-REPORT.md`, `tests/`가 저장소 최상위에 오도록 합니다.
5. **Commit changes**를 누릅니다. ZIP 파일 자체를 업로드하거나 폴더를 한 단계 더 감싸면 안 됩니다.

파일 구조:

```text
저장소 최상위/
  index.html
  config.js
  sync.js
  sync-core.js
  sw.js
  schema.sql
  vercel.json
  README.md
  TEST-REPORT.md
  fonts/
    PretendardVariable.woff2
    LICENSE.txt
  vendor/
    supabase.js
    SUPABASE-LICENSE
  tests/
    sync.test.cjs
    database.test.mjs
```

기존 저장소를 쓰고 있다면 같은 이름의 파일을 교체합니다. HTML 한 개만 바꾸면 동작하지 않습니다. GitHub에 커밋된 개인 JSON 백업이나 인증 토큰은 없어야 합니다.

## 5. Vercel에 배포합니다

기존 저장소와 Vercel이 연결되어 있다면 커밋 후 자동 배포를 기다리고, **Deployments**에서 최신 배포가 성공했는지 확인합니다.

새 프로젝트라면 https://vercel.com/new 에서 GitHub 저장소를 **Import**하고 아래처럼 설정합니다.

| 설정 | 값 |
|---|---|
| Framework Preset | `Other` |
| Root Directory | `index.html`이 있는 저장소 최상위 |
| Build Command | Override를 켜고 비워 둡니다 |
| Output Directory | `.` |
| Install Command | 별도 설치 없음, 필요하면 Override 후 비워 둡니다 |
| Environment Variables | 추가 불필요 |

**Deploy**를 눌러 나온 정식 주소를 기록합니다. 예: `https://my-japanese.vercel.app`.

`vercel.json`에도 빌드 없는 정적 배포와 출력 폴더가 지정되어 있습니다. 이후 GitHub의 운영 브랜치(보통 `main`)에 커밋하면 Vercel이 다시 배포합니다. [Vercel Git 배포](https://vercel.com/docs/git), [빌드·출력 설정](https://vercel.com/docs/builds/configure-a-build).

## 6. 이메일 로그인 주소를 설정합니다

Supabase **Authentication → URL Configuration**으로 돌아가 다음을 입력합니다.

| 항목 | 예시 |
|---|---|
| Site URL | `https://my-japanese.vercel.app/` |
| Redirect URLs | `https://my-japanese.vercel.app/` |
| 로컬 시험용 Redirect URL, 선택 사항 | `http://localhost:8000/` |

반드시 실제 배포 주소로 바꿉니다. 이 사이트는 현재 페이지의 `origin + pathname`을 로그인 후 돌아갈 주소로 보내므로 루트에서 쓴다면 **끝의 `/`까지 같은 주소**를 등록합니다. 사용자 도메인을 사용한다면 그 주소도 등록합니다. Vercel의 임시 Preview 주소를 쓰려면 해당 주소를 추가해야 하며, 운영용으로는 고정 도메인을 권장합니다.

**Authentication → Email Templates → Magic Link**에서 링크가 `{{ .ConfirmationURL }}`을 사용하도록 유지합니다. 이미 템플릿을 바꿨다면 기본 Magic Link 템플릿의 링크 방식으로 복원합니다. 이 사이트는 코드 입력 방식이 아닌 **이메일 링크 방식**입니다.

Supabase 기본 메일 발송은 수신 대상·발송량에 제한이 있을 수 있습니다. 실제 사용자 이메일에 배달되지 않으면 **Authentication의 이메일 발송/SMTP 설정과 Auth 로그**를 확인하고, 필요한 경우 본인의 SMTP를 설정합니다. 메일 발송 제한은 사이트 코드에서 우회하지 않습니다.

근거: [이메일 링크 로그인](https://supabase.com/docs/reference/javascript/auth-signinwithotp), [허용할 이동 주소](https://supabase.com/docs/guides/auth/redirect-urls), [이메일 템플릿](https://supabase.com/docs/guides/auth/auth-email-templates).

## 7. 첫 로그인과 기존 진도 이전

1. 기존에 공부하던 브라우저에서 **같은 사이트 주소**를 엽니다.
2. **데이터 관리 → 이메일로 가입 · 로그인**에 이메일을 입력합니다.
3. 받은 메일의 링크를 눌러 사이트로 돌아옵니다. 처음 사용하는 이메일이면 계정이 만들어집니다.
4. **데이터 관리 → 이 기기의 기존 기록 가져오기**를 눌러 확인합니다.
5. 위쪽에 **동기화 완료**가 표시될 때까지 기다립니다.
6. 휴대폰에서 같은 정식 주소를 열고 **같은 이메일**로 로그인합니다. 서버 기록이 자동으로 내려옵니다.

구버전 `haruharu-japanese-v1` 기록은 첫 실행 때 로컬 보관함으로 복사하며 원본 키는 지우지 않습니다. 로그인하면 계정별 보관함으로 전환하므로, 로그인 직후 기존 진도가 일시적으로 안 보일 수 있습니다. **기존 기록 가져오기**로 명시적으로 현재 계정에 합칩니다. 기존 계정에 이미 있는 완료/오답 항목은 유지하고, 없는 항목을 추가하며, 날짜별 학습 수업은 합칩니다.

한 계정으로 가져온 구버전 보관함은 다른 계정으로 다시 자동 이전하지 않습니다. 각 계정의 로컬 저장소는 분리됩니다. 업데이트 후에도 로그아웃 상태에서 더 공부했다면 같은 계정으로 다시 가져올 수 있습니다.

사이트 주소를 바꿨거나 다른 브라우저로 옮겼다면, 1단계에서 받은 JSON을 **로그인 후 JSON 백업 복원**으로 넣습니다. 이 복원은 현재 계정 기록을 바꾸므로 먼저 현재 기록도 백업합니다.

## 8. 자동 동기화·오프라인·충돌의 의미

| 표시/상황 | 동작과 할 일 |
|---|---|
| 기록 불러오는 중 / 동기화 중 | 계정 기록을 불러오거나 서버에 전송 중입니다 |
| 변경 저장 중 | 기기에 먼저 저장하고 약 0.7초 후 전송합니다 |
| 동기화 완료 | 서버의 저장 응답을 확인했습니다 |
| 다른 기기의 변경 | 사이트가 열린 동안 15초마다, 다시 활성화할 때, 연결이 돌아올 때 확인합니다 |
| 오프라인 | 이 기기에 변경을 보관하고 연결 후 재전송합니다 |
| 동기화 오류 | 기록을 보관하고 15초 간격으로 재시도합니다; 연결·로그인·SQL을 확인합니다 |
| 충돌 | 같은 항목이 서로 다르게 바뀌어 선택이 필요합니다 |
| 저장 공간 오류 | 기기 저장에 실패했습니다; 탭을 닫기 전에 JSON 백업합니다 |

서로 다른 수업의 변경은 자동으로 합칩니다. 같은 날 서로 다른 수업을 완료했다면 날짜 기록도 합칩니다. 같은 완료 기록/오답 항목을 서로 다르게 변경하거나, 한 기기에서 삭제한 항목을 다른 기기에서 바꿨다면 자동으로 덮어쓰지 않습니다.

**충돌 시 데이터 관리에서 먼저 JSON 백업**을 받고, `충돌 항목: 이 기기 기록 선택` 또는 `충돌 항목: 서버 기록 선택`을 누릅니다. 선택은 충돌 난 항목에만 적용되며 나머지 항목은 합쳐집니다. 여러 충돌 항목은 한 번에 같은 쪽을 선택합니다. 선택하지 않은 충돌 항목 값은 최종 기록에서 빠질 수 있으니 백업 후 결정합니다. 서버의 revision을 비교해 저장 도중 다른 기기가 먼저 저장한 경우도 다시 합칩니다.

오프라인에서도 **한 번 온라인으로 열어 파일 캐시가 준비된 기기**에서는 사이트를 다시 열 수 있습니다. 새 기기에서 처음 여는 경우에는 인터넷이 필요합니다. HTTPS 또는 localhost에서만 오프라인 캐시가 동작하며, `file://` 실행은 지원하지 않습니다. 사이트 파일만 캐시하고 Supabase 인증·학습 데이터 응답은 캐시하지 않습니다. 인증 토큰과 계정별 학습 기록은 브라우저 저장소에 보관됩니다.

기기를 잠그거나 탭/브라우저를 닫으면 주기적 동기화도 멈춥니다. 다음에 열 때 다시 확인합니다. 이 버전은 웹소켓 실시간 수신이 아니라 **최대 약 15초 간격의 자동 동기화**입니다. 네트워크 요청이 오래 멈추면 약 12초 뒤 오류로 처리하고 재시도합니다.

공용 컴퓨터에서는 JSON 백업 후 로그아웃하고 필요하면 해당 사이트의 브라우저 데이터를 지웁니다. 로그아웃해도 미전송 기록 복구를 위해 계정별 로컬 기록은 남습니다. 브라우저 데이터를 지우기 전에는 반드시 **동기화 완료**를 확인합니다. 기기 저장소 자체를 삭제한 뒤의 미전송 기록은 복구할 수 없습니다.

## 9. 배포 후 실제로 확인합니다

아래는 본인의 Supabase 프로젝트가 있어야 실행할 수 있는 최종 확인입니다.

1. PC에서 로그인하고 1일 차 수업을 완료합니다. **동기화 완료**를 확인합니다.
2. 휴대폰에서 같은 계정으로 로그인합니다. 1일 차 완료와 날짜 기록이 나타나는지 확인합니다.
3. 휴대폰에서 2일 차를 완료하고 PC에서 15초 이내에 반영되는지 확인합니다.
4. PC 인터넷을 끊고 다른 수업을 완료합니다. 다시 연결했을 때 휴대폰으로 전송되는지 확인합니다.
5. 두 기기에서 같은 수업을 서로 다른 시각에 완료한 뒤 충돌 표시와 두 선택지를 확인합니다.
6. 별도 이메일 계정으로 로그인했을 때 첫 계정의 진도가 보이지 않는지 확인합니다. 두 번째 계정에서 기존 기록 가져오기는 누르지 않습니다.
7. 기존 JSON 백업 복원·오답 삭제·기록 초기화가 다른 기기로 반영되는지, 시험 기록을 백업한 상태에서 확인합니다.

## 10. 문제가 생겼을 때

| 증상 | 확인할 곳 |
|---|---|
| 로그인 버튼이 설정을 요청함 | `config.js` 두 값, 배포 완료 여부 |
| 메일이 안 옴 | 스팸함, Email 가입 허용, Auth 로그, SMTP/메일 발송 제한 |
| 메일 링크가 잘못된 곳으로 이동 | Site URL, Redirect URLs, 정식 도메인과 끝 `/`, 이메일 템플릿 |
| 테이블/함수 없음 오류 | 같은 Supabase 프로젝트에서 `schema.sql` 전체 실행 |
| permission denied / RLS 오류 | SQL 전체 재실행, 실제 로그인 여부; 보안을 끄지 않습니다 |
| 로컬 모드가 계속 표시됨 | 배포된 `config.js` 값이 비어 있지 않은지 확인하고 새로고침 |
| 구버전 화면이 계속 나옴 | 사이트 탭을 모두 닫고 다시 접속; 새 파일 배포 시 `sw.js`의 CACHE 버전도 올립니다 |
| 기존 기록이 보이지 않음 | 원래 주소·브라우저인지 확인 후 기존 기록 가져오기 또는 JSON 복원 |
| 프로젝트가 응답하지 않음 | Supabase Dashboard에서 프로젝트 상태 확인 |

## 11. 개발자용 검증

기본 기능과 동기화 상태 머신 시험은 Node.js 20 이상에서 외부 패키지 없이 실행합니다.

```sh
node --test tests/sync.test.cjs
```

SQL/RLS 시험은 독립 PostgreSQL 엔진인 PGlite를 설치한 뒤 실행합니다. 실제 Supabase 계정이나 비밀 키가 필요 없습니다.

```sh
npm install --no-save @electric-sql/pglite@0.3.14
node tests/database.test.mjs
```

로컬 웹 미리보기:

```sh
python3 -m http.server 8000
```

브라우저에서 `http://localhost:8000/`을 엽니다. Supabase Redirect URLs에도 이 주소를 추가합니다. 테스트 의존성 설치로 생긴 `node_modules`는 GitHub에 업로드하지 않습니다.

검증 범위와 실제 서버 미검증 항목은 `TEST-REPORT.md`에 기재했습니다.
